# 关卡最终设计（主线 224 关 + 无尽段）

> **这是关卡的唯一真源。** 原理与实测数据来源见 `docs/关卡体系设计.md`（附录），
> `docs/玩法扩展设计.md` 的 M1-M7 已全部落地、其第三/五节作废。
> 定稿日期：2026-10-16。

## 最终口径（先读这 7 条）

1. **全部预生成。** 内容在构建期定死，运行时不"长"出新关。表里存 `map + 参数 + seed`，
   `generate(index, def.seed)` 是纯函数——同一关所有人打到同一盘，可讨论"第 137 关那个巧手"。
2. **没有"人工关卡"这回事。** `map` 只描述形状、不带花色，牌面永远是 seed 派生。
   所以逐关表那一列叫**审阅档位**而不是制作方式：`钉审`＝作者试玩并钉死 seed，
   `抽审`＝验收线自动筛 + 批量切图抽查。区别是审阅成本，不是生产工艺。
3. **关卡是固定谜题。** 现在 [Session.ts:161](../cocos/assets/scripts/core/Session.ts#L161)
   的 `reset(fresh=true)` 会翻 seed，重开同一关换一副牌——与关卡制矛盾，要改。
4. **一条无尽阶梯，不加模式。** 225 关起由预生成的无尽池接管（第十七节）。
5. **单关 4-7 分钟封顶，一章约 1 小时。** 牌位只决定玩多久，不决定难不难。
6. **规则放宽一分，约束收紧一分**（方言/财神必须配补偿项），这条进验收断言。
7. **埋点排在曲线之前**：没有每关进入/失败/放弃的数据，所有区间参数都是猜。

## 字段说明

- **盘面**：行×列。牌位（slots）由盘面与叠层共同决定，列出的数字是该关牌位目标。
- **牌位**：只决定"这关玩多久"，**不用于调难度**（原理二）。
- **花色**：`def.faces`。这是真正的难度旋钮（越多越难撞对）。
- **白送**：开局直接相邻的同面对子数上限（`sameFacePairs`）。
- **预算**：`moveLimit = par × 系数`；`时 ×N` 表示 `timeLimit = par × N 秒`。
- **审阅**：`钉审`＝作者试玩 + 钉 seed（每章 4 关：首见、招牌、变体、章末）；
  `抽审`＝批量出关后由验收线筛、切图抽查。**两者生产方式相同，都是预生成。**

## 二、十四章走法（每章 16 关，逐关数据见 `docs/关卡全量表.md`）

> 逐关的 224 行**不再手写**。`cd cocos && npm run export:table` 从 `core/levels.ts`
> 生成 `docs/关卡全量表.md`（盘面/牌位/花色/叠加/目标/预算/参考解/哑弹/审阅档/seed）。
> 手抄一份就会和真源分家——以前"文档说 15 个目标关、实际目标够不着"就是这么来的。

每章的固定节奏（关内位序 `k`）：**k=0 首见、k=8 招牌、k=13 变体、k=15 章末**，这 4 关要人试玩并钉审；
其余 12 关由跑批出、按验收线自动筛 + 切图抽查。

| 章 | 走法 |
| --- | --- |
| 1 推与点 | 只教"拖一轨、碰一对"。首见关不给障碍，第 5 关起撒空洞、第 7 关起放木桩、第 9 关起叠双层。全程不限步。 |
| 2 钉住 | 锁行（第 17 关首见）→ 锁列（第 23 关）→ 三层（第 25 关）。考点是"这一条推不动，那就换一轴"。限步从这章开始。 |
| 3 方向与链条 | 单向轨（只能朝箭头方向推）→ 连锁解锁（消够 N 对自动开一条轨）。这章开始盘面稳定 6×7，靠约束而不是牌位加压。 |
| 4 冰封 | 冰（配对只碎冰、牌留原地，要再消一次）→ 厚冰（碎两次）→ 鞭炮（配对时震碎同款冰）。前 15 关完全没冰，冰在这里一次性铺开。 |
| 5 订单 | 目标关（不必清台，先达成目标）+ 花牌入池 + 财神（百搭）首登场；**限时也在这章首次出现**（每章 k=5/9/14 三关走限时，其余走限步）。 |
| 6 将将胡 | 方言一：只有 2、5、8 能配对，其余牌是哑弹（滑块）。玩家看到的是白话"这一关只有 2、5、8 能消"，章名只用在星图标题。 |
| 7 断门 | 方言二：某一门的牌**只能点消**，滑动带不走。配 18-22 种花色，是"通道很窄 + 手要准"的一章。 |
| 8 幺九 | 方言三：只有 1、9 和字牌能配（真实国士的定义就含字牌）。有效面 13 种，靠 1、9 都在边上/角上制造规划压力。 |
| 9 清一色 | 方言四：只有指定一门能配对，另外三门全当滑块。这一章哑弹比例最高，所以厚冰/鞭炮一律不给它。 |
| 10 八花齐 | 集组一：集齐春夏秋冬梅兰竹菊（各消一对即可），不必清台。花牌在这章是目标而不是财神，所以整章 `wild:false`。 |
| 11 三元齐 | 集组二：集齐中發白。三种目标、盘更大，考"要不要为一对中發白专门腾一次推"。 |
| 12 清龙 | 集组三：按顺序把同一花色 1→9 各消一对。是"集齐一组"的最长版，也是全表参考解最长的一章（上限 80 步）。 |
| 13 双方言 | 方言 × 方言：偶数关带方言、奇数关走纯高压清台（花色回到 24-32），避免"章章砍白名单"把难度旋钮拧回去。 |
| 14 终章 | 全机制混合 + 最紧预算（步 ×1.25、时 ×2.1），白送对子 0、锁轨冲突 0；k=15 是双预算考试。 |

## 四、验收线（每关必过）

1. `certify()` 通过（存在可清台证书）；
2. par 落在该关位目标区间（对应单关 4-7 分钟，**超过 7 分钟直接丢弃重生成**）；
3. 白送对子 ≤ 该章上限、锁轨冲突 = 0；
4. 方言关：哑弹比例 ≤55%、有效面 ≥3 种；
5. 与前一关"配方距离" ≥1 栏；
6. 盘面：空洞/木桩不成片、左右不完全对称、牌位两色配平；
7. 含宽规则的关必须有补偿项（锁轨↑或白送↓）。

## 五、生产方式：全部预生成 + 种子冻结

### 15.1 为什么是预生成

| | 预生成（定稿） | 运行时生成 |
| --- | --- | --- |
| 进关等待 | 0 次搜索，只跑一次纯函数（实测 48.4ms/关，早先 3 种子口径 61ms 均值、553ms 最坏；真机按 3-5 倍算） | 同样要跑，且失败必须在线降级 |
| 质量 | **构建期可把丑关、无聊关全筛掉**，包里每关都过验收线 | "可解"不等于"好看"，玩家当试验品 |
| 一致性 | 全服同关：可讨论、可对照、每日挑战天然成立 | 每人不同，聊不到一起 |
| 审阅 | 钉审关的试解经验能复现给玩家 | 作者看到的和玩家看到的不是同一盘 |
| 成本 | 1000 关约 174KB（实测一关序列化 164B + seed 字段） | 运行时 CPU + 兜底逻辑 |

当前上传包 2,232,533 字节（2.23MB / 主包上限 4MB），**1000 关直接进主包，不需要分包**。

### 15.2 预生成的两种形态，选前者

| | **A · 钉 seed**（选） | B · 烘焙牌面 |
| --- | --- | --- |
| 表里存 | `LevelDef.seed?: number` | 每格每层的具体花色 |
| 包体 | 1000 关约 174KB | 每关 3-5 倍，1000 关约 0.5-1MB |
| 开局 | 仍跑 `construct()`（48-61ms） | 零计算 |
| 风险 | 无 | `map` 参数与 `grid` 成双真源，会漂移（改 `faces` 后老牌面即非法） |

**决定性理由：生成器无论如何都得留在包里。** 洗牌道具是 `redeal()` 按剩余牌重排
（[Generator.ts:282](../cocos/assets/scripts/core/Generator.ts#L282)）、撤销与百搭混对也走它，
所以 B 只省掉一次开局计算、省不掉代码，不值那个包体和双真源。
B 留作**低端机首帧优化**：等遥测给出真机耗时，再对个别重关单独烘 grid。

### 15.3 种子冻结规矩（不定这条，预生成自己会翻车）

> **实施时的修正**：只钉 `seed` 挡不住"改引擎"。实测：`map` 一字未改的 120 关里有 30 关的
> 参考解变了，因为 `Generator` 本轮被重写过——`关卡内容 = f(map, params, seed, 引擎实现)`。
> 所以真源是**一对**字段：`seed`（哪一副）+ `hash`（`Rules.boardHash` 的盘面指纹，长什么样）。
> 冻结判据是指纹而不是种子号；生成器一旦变动，`levels-seed.test.cjs` 会指名哪些关
> "种子还在、盘已经不是那一盘"，跑批同时打印 `换盘 N 关` 并要求重拍切图。

1. `LevelDef.seed` + `LevelDef.hash` 一旦写进表就是真源；`author-levels.cjs` **只补空、不覆盖**。
   工具的形状搜索用 `0xFACE + i * 7919 + attempt * 104729`
   （[author-levels.cjs:306](../cocos/tools/author-levels.cjs#L306)），
   改一行工具代码就会让全部已有关卡内容漂移——玩家打过的第 50 关下次进去换了副牌。
   需要重钉时用显式开关 `--reseed <范围>`。
2. 新增门禁测试 `tests/levels-seed.test.cjs`：每条已钉 seed 的关必须
   ① `generate(i, def.seed)` 不抛、② par 落在该关位区间、③ 第十四节 7 条验收线复算通过。
   它同时是"工具改动是否造成漂移"的哨兵。
3. **重开语义要改**：[Session.ts:161](../cocos/assets/scripts/core/Session.ts#L161) 的
   `reset(index, fresh=true)` 现在无条件翻 seed，导致重开同一关是换一副新牌。
   改为 `def.seed` 存在时不翻——关卡是固定谜题，背板重来应该看到同一盘。
4. 存档不受影响：`restore()` 直接吃 grid 快照（[Session.ts:60](../cocos/assets/scripts/core/Session.ts#L60)），
   不靠 seed 重算；洗牌仍走 `seed + revision * 7919` 派生，与钉种子不冲突。
5. 工程前置：author 工具慢在形状搜索（每关最多 120 次候选 × 3 种子）。120 关能忍，
   500-1000 关要先加**地图池复用 + 多进程分片**，否则一次跑批以小时计。

## 六、无尽段（225 关起）

主线 224 关是"有考点的关"的上限——滑轨语法可教的东西就十几项，硬把 1000 关都写成新课，
后 800 关只能调参数，那正是 101-120 翻过的车。1000+ 关住在这里。

- **入口不变**：还是一条阶梯、只有"下一关"。`levelAt(i)`：`i < 224` 查主表，
  否则查预生成的无尽池（`levels-endless.ts`，每 100 关一片）。
- **难度不无限增长**：采样包络把无尽段稳在第 8-10 章区间。

| 旋钮 | 无尽段取值 | 说明 |
| --- | --- | --- |
| 牌位 | 60-72，**不再往上涨** | 防止重演 12 分钟一关 |
| 花色 | 30→38 | 后期主要难度来源 |
| 白送对子 | 0 | 与第十章同档 |
| 可用滑轨 | 55-70% | 靠锁轨/单向/连锁组合压 |
| 机制 | 从 {冰, 厚冰, 鞭炮, 三层, 单向, 连锁, 目标, 限时, 4 种方言} 取 2-4 个 | 变化来源 |
| 预算 | 步 ×1.15-1.4；时 ×2.0-2.6 | 限时与限步不同时压（除"考试档"） |

- **组合空间够不够**：盘型 6 种 × 机制子集 C(8,2..4)=154 × 预算 3 档 × 花色 3 档 ≈ **8300 种配方**，
  每种再取多个 seed。所以 500 或 1000 关可以做到不重样、且每关有明确考点。
- **主题周**：每周从池里按主题取一段（本周冰 / 本周限时 / 本周将将胡），
  让无尽段有节奏，同时它是**不需要发版的内容公告**。
- **每日挑战共用这口池**：`seed = 当天日期` → 取池里第 `dayOfYear mod 池长` 关，全员同关、记连续天数。
- **进度显示**：选关屏一章一屏 4×4、共 14 屏（原「我的进度」弹框已并入选关，设置里只留开关与玩法说明）；无尽段不进这张图，

## 九、不粉饰的代价

1. **没有埋点之前，曲线全是猜的。** 秒/步这个数没有实测支撑，±40% 就能把"10 小时"变成 5 或 12 小时。
2. **审阅关卡的手感一定优于抽审关。** 生成器保证"可解"，不保证"漂亮"；审美过滤能缓解，但会把跑批时间推高。
3. **钉死 seed 之后工具改动受限。** 这是预生成的必然代价——好处是内容稳，坏处是"想全局重排"必须走 `--reseed` + 全量重验。
4. **顺子会显著抬 par**（排三元组比排二元组难），单关时长可能涨 1.5-2 倍，所以顺子章必须同时砍牌位。
5. **麻将门槛会收窄用户。** 缓解：前 22 关零方言；章节标题可用方言名（勾人、可传播），但关卡内那句必须是白话——"这一关只有 2、5、8 能消"。
6. **审核风险**：麻将题材在小游戏里属敏感区。术语本身（碰/杠/胡/财神）没问题，但**"财神"只做牌面叫法，绝不接金币、兑换、提现语义**；收集物类表现一律不做（同时解决"没美术"和"审核风险"）。
7. **本文档取代不了试玩。** 所有取值区间都是推算的，要第 1 批方言关真机打过之后回调。
