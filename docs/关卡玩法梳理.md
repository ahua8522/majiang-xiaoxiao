# 关卡玩法梳理（2026-10-15 · 120 关版）

> 数据来源：`cocos/assets/scripts/core/levels.ts`（由 `npm run author:levels` 生成）+ `cocos/tools/audit-levels.cjs` 盘点。
> 每关都经过验证：存在可清台路线、偶/奇色牌位完美匹配、棋盘两两不同、限步关的步数上限 ≥ 证书步数。

## 三、长方形棋盘（已落地）

屏幕约束：`cellW = min((750-108)/cols, availH/rows/1.24, 116)` → 行 ≤ 10、列 ≤ 9。
101-110 用 8×5、111-120 用 9×5 / 10×6 —— 竖长盘让「锁 2 行」占到 20~40% 的行，障碍密度也更高（同样 6 个木桩，40 格是 15%、72 格只有 8%）。
难度不来自「长方形」本身（长轨反而更好推），而来自**锁轨占比 + 障碍密度 + 冰面/叠层密度**。

## 四、生成器侧的硬约束（踩过的坑）

1. **证书重放必须用生成时的 runs**：滑轨按「哪些格有牌」算出来，牌消掉后结构会变；每步重算会让逆操作打到别的轨上，留下孤儿牌（第 79 关曾直接生成失败）。
2. **冰面必须成对碎**：只碎单张会让一对变成「一张露脸一张带冰」，永远配不上。鞭炮因此改为「按面整组震碎」。
3. **锁轨上的白送对子只能在打乱打分里罚**：锁行/锁列会被垂直方向的轨带进带出，锁轨格的内容取决于打乱结果。
4. **爬山要限步**：局部爬山每接受一步都会给证书加一个滑轨动作（膨胀 par），上限 12 步。
5. **出关重试**：偶尔有种子摇不出证书（约 4%），`construct` 用确定性派生种子重试 6 次，保证玩家不会进关就崩。
6. **鞭炮不能留在随机池里**：`FACES` 含鞭炮（图集/存档校验用），但随机池必须过滤掉，否则数量翻倍、难度失控。
7. **限步按证书总步数（取三种子最大）推导**，不是按「消除对数」——证书里主要工作是滑轨的连锁消除（92 张牌可能只有 3 次显式配对）。

## 五、死局判定（玩家实测 bug 的修复）

现象：最后剩一叠孤牌时，既不判失败也不判成功、也无法消除。
根因：旧判定用**缓存的 runs**（牌消掉后已过期，指着空格），求解器以为牌还能滑，一路探索到预算耗尽返回 `unknown`，而 `unknown` 按设计不判死。
修复：`Rules.isDead()` —— 按传入盘面**重算滑轨**，穷尽「无进展状态空间」，只有确实走不出去才返回 true；预算用尽一律不判死。
配套：Session 每次消除后重算 runs（顺带支撑连锁解锁），视图在落子后读 `session.dead`；失败页区分「步数用尽」与「牌走死了」，并给「撤销一步」按钮。
