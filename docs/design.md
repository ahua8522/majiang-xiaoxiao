# 麻将小游戏 · 完全重构设计

## 1. 目标

把现有「平台无关 Command 绘制 + GameRoot 薄适配」的架构，改为**直接用 Cocos 组件**实现；同时重做配色、logo、关卡体系，去掉多余文案。

## 2. 现状问题（均有实测证据）

| 问题 | 证据 |
|---|---|
| 视图层不伦不类 | 1436 行脚本里 1058 行是平台无关的 `core`/`view`，只有 378 行 `GameRoot.ts` 真正用 cc；所有画面靠 `Graphics` 逐帧重建 `Command[]` |
| 绘制开销集中在牌面 | 一帧平均 637 条命令 / 103,144 顶点，**牌面占 94%**；第 13 关 28 层 Graphics ≈ 7.0 MB 顶点缓冲、28 个 draw call |
| 单张牌太贵 | 平均 2,276 顶点 / 13.5 条命令；牌身恒为 1,404 顶点（每张牌相同），9 筒因 27 个圆达 6,804 顶点 |
| 配色老气 | 深绿毛毡 `#235B48` + 木色 `#E7BA80` + 米白 `#FAF5E9`，低饱和「茶馆」调 |
| 设置按钮 bug | 从首页点「设置」，`render()` 实际画出的是**牌桌**（已复现：`首页=false 牌桌=true`）。根因是 `render()` 只特判 `open==='home'`，其他弹窗一律以牌桌为底图；`returnModal` 存在于 Session 但未暴露给视图 |
| 关卡重复 | 18 关只用到 8 种棋盘形状，**15 关挤在 5 种里，第 13～18 关是同一块 7×8 骨架**。根因：关卡由 `levelAt()` 的算术规则推导，`stage` 只有 6 档 |
| 文案冗余 | 「麻将小茶馆」「一方牌桌 · 一盏清茶」等装饰性文案占位过多 |

## 3. 决策（已与用户确认）

1. **视图层全部用 cc**：Node / UITransform / Graphics / Label / Sprite / Tween / Widget / ScrollView / Layout。规则层保持纯 TS（cc 不提供规则能力）。
2. **配色用方案 A「糖果卡通」**：奶油暖底 + 珊瑚橘主行动色，牌做成厚塑料牌（粗描边 / 大圆角 / 实心向下投影）。牌背按花色分色：筒蓝 `#3B9BFF` / 条绿 `#22C55E` / 万红 `#FF5252` / 字紫 `#A855F7`。
3. **logo 用代码画**：三张牌 + 萬 / 乐 / 筒，不引入美术资源。
4. **关卡数据驱动，共 100 关**，每关独立设计；去掉章节分组与关卡数量显示。
5. **验证通道只走 cc**：删 `preview/` 与视图测试；规则层保留 node 单测；cc 代码用 `npm run check:cocos`（`@cocos/creator-types`）类型校验。

## 4. 新架构

```
assets/scripts/
  core/                     规则层（纯 TS，不依赖 cc，保留 node 单测）
    Rules.ts                滑动 / 配对 / 连消 / 提示搜索
    levels.ts               100 关数据（由 tools/author-levels.cjs 生成）
    Generator.ts            按关卡数据摆牌 + 打乱 + 生成已验证清台路线
    Session.ts              评级 / 辅助 / 存档 / 弹窗状态机
  theme.ts                  设计令牌（色板 / 圆角 / 描边 / 厚度 / 排版）
  view/                     视图层（全部 cc 组件）
    TileArt.ts              牌面绘制（按花色分色，Sprite 化）
    Board.ts                牌桌：节点池 + 拖动预览 + 消除动画
    Hud.ts                  顶栏 + 底部工具条
    Overlay.ts              弹窗：设置 / 玩法 / 重开 / 胜利 / 选关
    Home.ts                 首页（logo + 继续 + 选关 + 设置）
    GameRoot.ts             场景根，装配以上并驱动 Session
```

边界：`core/` 与 `theme.ts` 不 import `cc`；`view/` 可以。这是唯一保留的约束，用来保证规则仍可单测。

## 5. 关键设计点

- **导航状态**：Session 增加 `returnModal` 的对外只读视图，视图据此决定弹窗底下画哪一屏（修掉设置按钮 bug）。
- **牌面**：34 种牌面（9 筒 + 9 条 + 9 万 + 7 字）。每种用 `Graphics` 画一次到 `Node`，之后复用节点，不再逐帧重建命令。
- **布局**：全部用 `UITransform` + `Widget` 显式定位，不再有「设计像素 → 实际像素」的手工换算层。
- **触摸**：每个可点节点挂自己的 `Node.EventType.TOUCH_END`，不再维护 `hits[]` 数组做手工命中测试。
- **动画**：消除特效与弹窗进出用 `tween`。
- **选关**：扁平网格 + `ScrollView`，不分组、不显示总数。

## 6. 验证策略

| 层 | 手段 |
|---|---|
| 规则 / 关卡 | `node --test tests/`（100 关可清台、两两不同、难度递进、存档迁移） |
| cc 视图 | `npm run check:cocos` 类型校验（`@cocos/creator-types`，当前 0 报错） |
| 产物 | Cocos 编辑器预览 + 微信开发者工具（本机启动较慢，作为最终验收） |

## 7. 明确不做

- 不引入任何美术资源（图片 / 字体 / 音效）。
- 不引入引擎的高级模块（物理 / 3D / Spine），主包仍控制在 4MB 内。
- 不做章节、不做关卡数量显示、不做装饰性文案。
