# 章首玩法教学（手写小盘 + 硬引导）设计

日期：2026-10-18 · 分支：`feat/levels-224` · 状态：待实施
拍板人：wanqinghua（舞台=手写小盘 / 强度=硬引导只做一步 / 范围=14 屏 / 触发=机制首见通道）

## 一、要解决的问题

今天全游戏的教学只有一条通道：`LevelDef.intro` 键 → `TIP_CONTENT`（标题 + ≤4 行白话）→ `GameRoot.renderTipCard()`，一张读完即消失的文字卡；首页"玩法"只有 6 行静态文字（`GameRoot.ts:1104-1111`）。

把 224 关的 `intro` 分布实际跑出来的结果（`node -e require('.test/core/levels.js')`，非手抄）：

| 章 | 章名 | 首关 intro | 本章所有 intro | 章主题的实际载体 |
|---|---|---|---|---|
| 1 | 推与点 | `basic` | basic, stack | — |
| 2 | 钉住 | `lockRow` | lockRow, lockCol, moveLimit | — |
| 3 | 方向与链条 | **无** | oneWay, unlock（都在 k>0） | — |
| 4 | 冰封 | `ice` | ice, bomb, ice2 | — |
| 5 | 订单 | `flower` | flower, wild, goal | 目标关 3 个 |
| 6 | 将将胡 | `only258` | only258 | 方言 16/16 |
| 7 | 断门 | `noSuit` | noSuit | 方言 16/16 |
| 8 | 幺九 | `only19` | only19, stack3 | 方言 16/16 |
| 9 | 清一色 | `oneSuit` | oneSuit | 方言 16/16 |
| 10 | 八花齐 | `collect` | collect | collect 目标 16/16 |
| 11 | 三元齐 | **无** | **整章一个都没有** | collect `['z5','z6','z7']` ×3 |
| 12 | 清龙 | **无** | **整章一个都没有** | collect `['1p'..'9p']` |
| 13 | 双方言 | **无** | **整章一个都没有** | 方言 8/16（仅偶数关） |
| 14 | 终章 | **无** | **整章一个都没有** | 方言 8/16 + 最紧预算（parMax 105） |

诊断两条：

1. **5 个章（3、11、12、13、14）进关时屏幕上什么都不弹**，其中四个是终章——牌型最黑话、盘面最大（9×9、10×9）、参考解最长。玩家打到章 11 看到标题「三元齐」，得到的全部指导是顶栏一个进度数字。
2. **说明卡的粒度是「机制」，玩家的疑问是「牌型」。** 现有 `collect` 卡写"把这一组各消掉一对就通关"，讲清的是通关口径；但章 11 要他收「中·發·白」、章 12 要他收「一筒到九筒一条龙」，他缺的是"为什么这副牌叫这个名字"。这是麻将知识，不是操作知识，而它教的是一组牌**彼此的关系**——白话卡装不下。

## 二、已拍板的四个决定

1. **触发**沿用既有的"首见"通道（`tipsSeen` 持久化 record），不新增存档字段，`version` 保持 3。
2. **舞台**用**手写小盘**，插在进真关之前，跑真实 `Rules`。不采用"在真盘上教"（那条必须处理"这盘恰好没有要教的东西"——`wild:true` 实测 8 个百搭关有 4 关一张百搭都没发出来，教一个盘上不存在的东西比不教更糟）。
3. **强度**是硬引导，但**只管第一步**：小盘上只认目标动作，做完立刻收尾进真关，不把玩家锁在教学屏里。
   "一步"在这里定死为可检查的口径：**每屏 `need`（要玩家亲手做）的步骤不超过 2 个**——一次正例 + 一次对照（章 3 的"顺向推 / 反向推不动"、章 6 的"推一下消一对 / 再推一下啥也没消"、章 7 的"滑消带不走 / 点消能收"都属于同一"步"的对照表达），做完即放，整屏目标时长 ≤12 秒。
4. **范围**14 屏，每章一屏。内容单位 = **章主题/牌型**，不是机制的重复朗读。

## 三、内容清单：14 屏各教什么

牌型定义一律对着 `docs/关卡最终设计.md`、`docs/关卡玩法梳理.md` 与 `.test/core/levels.js` 的实际 `goal`/`dialect` 校验，**不许自己编规则名**。`z5/z6/z7 = 中/發/白`、`f1..f8 = 春夏秋冬梅兰竹菊` 的映射依据是 `Session.faceName`（Session.ts:121-128）。

| 章 | 小盘要点 | 玩家亲手做的动作 | 这一步的结论（= `expect`） |
|---|---|---|---|
| 1 推与点 | 2×3 全普通牌 | 推一行 / 点对两张 | 两种操作都能消；推能一次带走不止一对 |
| 2 钉住 | 带一条锁行 | 先推锁行，再推活轨 | 锁行 `changed:false`；活轨消一对 |
| 3 方向与链条 | 一条单向轨 + 一条带数字的锁轨 | 顺向推一次、反向推一次 | 反向不动；消一对后锁轨数字减少 |
| 4 冰封 | 一张冰牌 + 一张鞭炮 | 点对冰牌两次 | 第一次 `erased` 只碎冰、第二次才收走 |
| 5 订单 | 顶栏目标 + 一张百搭 | 收指定牌面的一对 | 目标计数前进；百搭能配任意牌 |
| 6 将将胡 | 见下节实测盘 | 推一行，**再推同一行** | 第一步消 2 筒；第二步 `changed:true / pairs:0` |
| 7 断门 | 缺门牌与别门牌同桌 | 先滑消带不走、再点消 | 滑消 `pairs:0`；点消 `pairs:1` |
| 8 幺九 | 1、9、字牌 + 中间牌 | 点对字牌，推中间牌 | 字牌能配；中间牌推得动配不成 |
| 9 清一色 | 只一门能配 | 推走别门、配同门 | 三门是滑块，`liveCount` 只看筒 |
| 10 八花齐 | 三种花牌 + 顶栏计数 | 收一种花牌的一对 | 集组按"这一种到手"计一次 |
| 11 三元齐 | 中·發·白 各两张 | 点对中 | **中不配發**：不同面之间不配对 |
| 12 清龙 | 一筒到九筒、故意缺五筒 | 把能配的推成对 | 缺一张就不算龙；顶栏只数收到的种数 |
| 13 双方言 | `ranks[2,5,8]` 与 `suit:'s'` 交集 | 推一次 | 交集只剩 2、5、8 条；另讲"本章只偶数关带方言" |
| 14 终章 | 冰 + 锁 + 目标同桌 | 收目标那一面 | 读盘顺序：先看目标与预算，再看障碍层 |

## 四、示例小盘的真实运行结果（已在真 Rules 上跑过）

章 6 的盘：`['2p','6s','2p'] / ['8m','5m','8m']`，方言 `{ranks:[2,5,8]}`：

- 开局 `pairs()` 0 条、`tapPairs()` 0 条、`runsFor` 5 条轨 → **不推就什么都消不掉**，教学必须靠动作。
- 步骤 1 推 row0 step+1 → `changed:true`、消 1 对（`2p`）、chain 1，盘面变 `[· · 6s] / [8m 5m 8m]`。
- 步骤 2 同一行再推 → **`changed:true`、消 0 对**，盘面变 `[6s · ·] / [8m 5m 8m]`。这一行就是整段教学的价值：**6 筒推得动，但配不成对**。方言"只改配对谓词、不碰滑轨"的设计，玩家只有亲手推第二下才看得懂。
- 此时 `liveCount=3`、`count=4`、`isDead=false` → 顺带讲清"剩下的哑弹不用管"。

## 五、架构与边界

### 5.1 章教学键不进关卡表

`intro` 是**跑批推导**的：`tools/author-levels.cjs:543` 的 `INTRO_RULES` 表 + `:810-813` 的"本章第一个命中该机制的关"赋值 + `:926` 序列化进 `levels.ts`。手改 `levels.ts` 会被下次 `npm run author:levels` 冲掉。

所以章教学键由视图/Session 就地推导，`levels.ts` 与 `author-levels.cjs` 一字不动：

```
章号 n = def.chapter ?? floor(levelIndex / 16)      // 与 Session.difficulty 同一口径（Session.ts:134）
键     = 'ch' + n
展示条件 = n < CHAPTER_NAMES.length && !tipsSeen[键] && CHAPTER_TUTORIALS[n] 存在
```

**比"绑死 k=0"更宽一点**：条件是"该章第一次被进入"，不是"这一关是章首"。玩家从选关页跳进章 6 的第 4 关，照样补上这一段；而教学内容与具体盘面无关（小盘是手写的），所以在哪一关插都不会错。

第 1 关今天的行为要改掉：现在 `chosen===0` 每次进都弹 `basic`（Session.ts:193）。它变成 `ch0` 教学屏之后不能每次弹——一个 8 秒的交互每开一次游戏重演一遍是打扰。改成首见弹一次。

### 5.2 复用 `Session.tip` 做屏蔽，不写第二套

`tip` 非空时已有六处挡住：`tick`(240)、`apply`(253)、`tap`(311)、`notice`(322)、`command`(399)，加 `setupLevel` 的赋值(193)。效果是牌桌输入被吞、限时关停表、状态不落盘。

教学屏期间让 `tip` 一直保持非空，教学结束走现成的 `dismissTip()`（172-178：写 `tipsSeen` + `save()` + `revision++`）。**这一处省掉的是最容易写出 bug 的一整块逻辑**，也避开「漏登记 `SCREEN_MODAL` 就每秒重播淡入」那一类事故（commit e82ec48）。

`Screen` 联合类型加 `'tutorial'`，`SCREEN_MODAL`（`Record<Screen, Modal>`，编译器强制穷举）加 `tutorial: 'none'`——停表靠 `tip`，不靠 modal。`DIALOG_ORIGIN` **不加**条目：教学屏只带一个「跳过」按钮，没有设置/玩法入口，缺省会继承来源=牌桌，正确。

### 5.3 教学控制器不碰 Session

控制器自己持 `grid / runs / dialect`，直接调 `Rules.transition()`。理由：`Session.reset()` 会发牌、落盘、推 `maxLevel`、定 `par`、算星级、进 `history`——教学目标一分钱都不能花掉这些。

自动演示与玩家操作**共用同一条 `advance(action)` 路径**，区别只在动作来源（脚本 or 手指）。这既省一半代码，又保证"演给他看的就是真规则"。自动演示的步骤间隔走 `update(dt)` 累加计时，与限时关同一个入口，不新增调度器。

### 5.4 渲染：`Board` 开第二个实例，零新纹理

`new Board(tutorialRoot, this.ui)`，`build()` 传现有 `TileAtlas`。牌图集只烘一张基准格、显示尺寸靠 `contentSize` 缩放（Board.ts:132-135），所以显存增量只有约 12 个 Sprite 节点。

**两条硬性约束**：

- 教学 Board **不能挂在 `screens.overlay` 下**——`render()` 第 483 行每次重绘都 `clearChildren(overlay)`，会把节点池连锅端掉。它要有自己的 `screens.tutorial` 根节点，Board 实例常驻、只 `build()` 重建，不随重绘创建销毁。
- 教学屏的重绘必须由控制器自己的 revision 驱动。`tip` 非空时 `tick` 返回 false、不跨整秒、不触发重绘，这是现有保证；不要为了"动一下"去加逐帧 dirty，否则淡入重播的老坑会重演。

显存这一句是推理，不是证据。实施时必须用现成的 `atlasDiag` 自检读数在真机预览里量一遍（这几个版本正是为显存和纹理上传路径改过三轮）。

### 5.5 硬引导的实现：只认目标动作，不挖遮罩洞

教学屏把手势解析成 `Action`，命中目标轨才 `transition`，然后拿 `expect` 校验结果决定这一屏走不走；不是目标轨就回弹并播一句「就推这条」。小盘只有 2×3，不需要靠"别的地方点不动"来表达强制，画洞反而多一套遮罩图形和一条命中分支。

### 5.6 降级是设计承诺，不是 try-catch 的心情

教学表查不到、`parseBoard` 失败、`transition` 抛异常、`expect` 与实际结果对不上——任何一种都立刻 `tip-ok` 进真关，行为退化成今天的文字卡。**教学永远是加法，不许变成进关的门槛。** 真机读不到 console，这条是唯一能兜住"教学在真机上炸了"的东西。

### 5.7 与文字卡去重

`dismissTip()` 里，若这一关同时命中机制首见（章 4 首关既是 `ch4` 教学又是 `ice`），两个键一起写进 `tipsSeen`。否则就是"小盘演完冰、进关又弹一张冰的文字卡"。

### 5.8 回看入口

`renderHelp()` 那 6 行白话改成 14 条章目录，点一条就地重放该段教学。回看走**同一个控制器的"只看"模式**：所有 `need` 步骤一律降级成自动演示，不要求玩家动手、不做输入拦截，看完点关闭回原屏——玩家可能只想扫一眼，重做一遍强制操作在回看场景里是打扰。同一份数据两处用。这是"文字说明空洞"的永久解：玩家忘了清龙收什么，不用重推到章 12。

## 六、教学脚本的数据格式

`core/tutorials.ts`，纯数据 + 纯解析，**不 import `'cc'`**（否则 node 测试链拿不到）：

```ts
interface Step {
  say: string;                                        // 这一屏说的一句话
  need?: 'slide' | 'tap';                             // 缺省 = 自动演示；给了 = 玩家亲手做
  on: {axis:'row'|'col'; index:number} | {tap:[Pos,Pos]};   // 意图，不是 runs 下标
  expect: {changed:boolean; pairs:number; faces?:string[]};  // 单测断言 + 运行时前进条件
}
interface Tutorial { title:string; board:string[]; dialect?:Dialect; lockR?:number[]; lockC?:number[]; oneWay?:OneWay[]; steps:Step[]; close:string }
export const CHAPTER_TUTORIALS: Tutorial[]   // 14 条，下标 = 章号
```

- **`on` 不写 run 下标**：`runsFor` 的数组顺序由盘面形状决定（先行后列），小盘一改格子，写死的下标就指到别的轨——**和第 75 关"解锁后 19→21 条、同一下标从 row4 变成 row2"是同一个 bug 家族**。运行时用 `runsFor(grid,lockR,lockC,oneWay).findIndex(r => r.axis===… && r.index===…)` 解析，格子随便挪。
- **`expect.pairs: 0` 是一等公民**：章 6 第二步的全部价值就是"滑轨推得动、牌配不成"，`changed:true / erased:0` 是结论，不是失败。
- 盘面字面量：`'2p'` 普通、`'5s~'` 一层冰、`'5s~~'` 厚冰、`'f3*'` 百搭、`'b1'` 鞭炮、`'#'` 木桩、`'.'` 空洞、`'3m|3m'` 叠两层（数组末尾为顶面，与 `top()` 一致）。

## 七、校验与验收

1. **门禁单测** `tests/tutorial.test.cjs`，挂进 `npm test` 那条链（现在 11 个测试文件）：遍历 14 条脚本 → `parseBoard` → `stateLegal`（偶数张、每面 ≤4 张）→ 逐步 resolve 成 Action → 跑真 `Rules.transition` → 断言 `changed` / `erased.length` / 牌面集合。任何一条红 = 教学上不了线，而不是上线后教错东西。
2. **`build:core` 要加文件**：`cocos/package.json` 的 `build:core` 目前只编译 levels/Rules/Generator/Session 四个，要加 `assets/scripts/core/tutorials.ts`，否则 node 测试拿不到这份数据。
3. **截图验收**（单测绿不等于看过画面）：走现成的 web-mobile 构建 + headless Chrome/CDP 那条路，14 章教学屏逐张截图，核对高亮位置、按钮命中、文字不出面板。
4. **`tsc -p tsconfig.check.json`**（`npm run check:cocos`）必须绿——`SCREEN_MODAL` 的穷举 `Record` 会替我们盯住新 Screen 有没有登记。

## 八、明确不做

不动 `levels.ts` 的 map/seed/hash/faces/parMax；不动 `Generator`/`certify`；不动 `Rules`；不加存档字段、不改 `version: 3`；不做重力下落等破坏置换不变性的东西；不把教学变成不可跳过；不改任何现有关卡的盘面数据。

## 九、实施顺序

1. 先做**章 6 将将胡一屏**，把整条链跑通：数据格式 → `parseBoard` → 控制器 → Board 第二实例 → 输入 → 降级 → 单测 → CDP 截图 → 微信预览。选它的理由：内容最硬（"推得动但消不掉"），且恰好依赖 `pairs: 0` 这种最容易被偷懒省掉的断言，用它验架构最狠。
2. 架构验过之后铺剩下 13 屏，每屏都过同一道门禁。
3. 文案与 `docs/关卡最终设计.md` 对账（牌型名、集组面、方言交集），不自己编。
4. 教学屏的显存与帧表现做一次真机预览测量，读数记进提交说明。

## 十、风险与未验项

- **显存**：第二个 Board 实例的节点成本推理约等于 0，但没量过。风险由 `atlasDiag` 读数收。
- **`Board` 的节点池与两个实例并存**：`playErase` 的幽灵牌、`setDrag` 的预览都按实例隔离，理论安全，需要真机验一次"教学屏和牌桌不互相拽牌"。
- **自动演示的时序**：`update(dt)` 在小游戏切后台时会掉帧，演示步骤间隔要钳制、不能假设 dt 连续。
- **14 屏 × 硬引导**：没上线，无老玩家兼容负担；但体验版试玩者会一次性拿到 14 段教学，第一版做完要自己从头推一遍章 1→章 6，确认打扰程度可接受。
