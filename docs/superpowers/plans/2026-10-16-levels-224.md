**Goal:** 把关卡体系从「120 关、每次重开换一副牌」改造成「224 关 / 14 章、内容预生成并钉死种子、带限时关与 7 种麻将方言」，并且每一步都让 `npm run test:all` 保持全绿。

## Global Constraints

- 单关目标时长 **4-7 分钟封顶，一章约 1 小时**（spec 最终口径 5）。
- 难度旋钮：`faces`（花色数）是难度，**牌位只决定玩多久**（原理二）。
- **规则放宽一分，约束收紧一分**：任何方言/百搭关必须有补偿项（原理一，进验收断言）。
- **一关只考一件事**；相邻两关配方距离 ≥1 栏。
- 每章 16 关，其中 **4 关钉审**（首见 / 招牌 / 变体 / 章末），其余抽审；`钉审`＝试玩 + 钉 seed。
- 方言关：**哑弹比例 ≤55%、有效面 ≥3 种**。
- 关卡数据真源是 `cocos/assets/scripts/core/levels.ts`，**它由工具生成**——`LevelDef` 接口体在 `tools/author-levels.cjs:433-459` 的模板里，只改 `.ts` 会在下次跑批时被覆盖。
- 测试前必须先 `npm run build:core`（`.test/core/*.js` 是编译产物）。
- `cocos/temp/mjshot.cjs gallery <start> <end>` 参数 **0 基、文件名 1 基**；改完代码要重新构建才看得到。
- 麻将术语可用（碰/杠/胡/财神），但 **"财神"只做牌面叫法，绝不接金币/兑换/提现语义**；收集物类表现一律不做。
- 密钥文件绝不入库（`*.key`/`*.pem`/`cocos/.secrets/` 已在 `.gitignore`）。
- 构建必须走编辑器 `auto-build` 扩展，CLI 构建会丢引擎裁剪。

  const a = process.argv.find(v => v.startsWith('--reseed'));

  const m = /^--reseed(?:=(\d+)?(?:-(\d+))?)?$/.exec(a);
  if (!m) throw new Error('--reseed 用法：--reseed 或 --reseed=81-96');

export function pairable(face: string, d?: Dialect): boolean {
  if (!d) return true;
  if (isWild(face)) return true;                                  // 财神永远能配
  const s = suitOf(face);
  if (s !== 'p' && s !== 's' && s !== 'm') return !d.ranks && !d.suit;   // 字/花/鞭炮：白名单关里当哑弹

}

## 执行期发现的计划缺陷（Task 1 实施时补进计划）

### 缺陷 1：钉 seed ≠ 钉内容（已修）

计划原本只钉种子。实施后第一次跑批做内容级比对，发现 `map` 一字未改的 120 关里有 30 关参考解变了
（第 43 关 `moveLimit` 36→33），而跨进程验证 `generate(i, seed)` 是确定的——
说明差异来自**生成器实现本身**：committed 的 `levels.ts` 是本轮重写 `Generator.ts` 之前生成的。

> 结论：`关卡内容 = f(map, params, seed, 引擎实现)`。种子只挡得住"改公式"，挡不住"改引擎"。

补法：`Rules.boardHash`（FNV-1a）+ `LevelDef.hash` 落表 + 冻结判据升级为**指纹比对** +
`levels-seed.test.cjs` 逐关用 `generate(i, seed)` 重算指纹。引擎一旦变动，门禁直接列出哪些关
"种子还在、盘已经不是那一盘"，跑批汇总打印 `换盘 N 关` 并要求重拍切图。

### 缺陷 2：(seed, hash) 必须描述"游戏真正会发的那一盘"（已修）

指纹门禁上线后自己报出 15 关不符，且**全部**是带 `goal` 的关。原因：工具先拿
`candidate`（还没填 `moveLimit` / `goal`）认证并记指纹，但 `goal` 会反灌生成器牌池、
`moveLimit` 会改变候选排序（`rankOf` 第一键就是超不超上限），最终定义发出来的是另一盘。
补法：认证拆成两阶段——阶段 1 用候选定 `moveLimit` / `goal`，阶段 2 用**最终定义**重新认证，
指纹与 `seed` 都取阶段 2 的结果。附带把限步基数从"三种子里最长的"改成"钉死那一盘的参考解"
（内容冻结之后跨种子方差已经不是玩家会碰到的东西），并删掉按别的种子抽样 8 次的旧质检
（它服务的是"玩家拿 Date.now() 发牌"的时代，现在全是噪音）。

### 决策 3：锁轨白送对子的回归——用离线挑种子解决，运行时不付钱

`锁轨冲突均值 ≤0.9` 这条测试擦线失败（0.909 / worst 19）。根因是本轮重写时为了省启动时间加的
"满足步数上限就提前返回"，它跳过了冲突最小化。实测两个方向：

| | 提前返回只看步数（现状） | 提前返回还要求零冲突 |
| --- | --- | --- |
| 随机 9 种子 0 冲突占比 | 70.5% | 89.6% |
| 均值 / worst | 0.909 / 19 | 0.481 / 16 |
| 每次进关耗时 | **113ms** | 261ms（真机估 0.8-1.3 秒） |

**用户拍板：离线保证发布盘面 0 冲突。** 于是冲突不再靠运行时搜索消除，而由跑批
`certifyDef` **扫至多 16 颗种子挑出 0 冲突那一盘**来保证；运行时保持快路径不变。
这条成立的前提正是缺陷 1/2 修好的东西：表里 `(seed, hash)` 精确描述了玩家会拿到的盘面，
所以"离线挑中的那一盘"和"运行时发出来的那一盘"是同一个东西。

配套的测试口径变更（`generation.test.cjs`）：拆成两条——
① **发布口径**（按钉死种子重算）：0 冲突 ≥95%、均值 ≤0.15；
② **生成器兜底**（随机 5 种子）：均值 ≤2.0，只防"完全不罚冲突"的数量级退化，注释写明它不是发布质量线。
