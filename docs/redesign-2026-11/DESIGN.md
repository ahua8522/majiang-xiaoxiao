# 快乐推麻对对消：晴日花园视觉方案

2026-11-05 · 全面改版方案与可交互设计稿

## 本次结论

**保留麻将牌、推移与配对消除；移除清一色、将将胡、幺九、断门及其组合限制。**

玩家应始终相信：两张相同牌相邻，就能消。机制深度来自“先消哪里、怎样移动、先完成哪个目标”，不再来自“这一关哪些麻将不准消”。

视觉方向调整为“晴日花园”：明亮日光、乳白实体麻将、青绿绒面、低对比植物、少量杏桃色按钮。麻将是主角，花园只提供放松的环境。移除茶馆、掌柜、茶客和经营叙事。女性休闲玩家是重点考虑人群，但风格不靠性别刻板印象；用可读性、轻松节奏、触感和通关收获建立吸引力。

### 本阶段的固定约束（按最新反馈更新）

- **备案身份保持**：游戏名称仍为“快乐推麻对对消”，保留麻将牌、万筒条与字牌、推移配对消除；“晴日花园”只是视觉方案标签，不是更名。AppID、备案文件、平台资料均未修改。
- **牌面更像实物**：乳白正面、细倒角、青绿背板，竹节连续；四条 2×2、六条 2×3 全绿、九条 3×3 中列红。以行列和数量为主要依据，颜色为补充。
- **完全本地运行**：本阶段不接服务器或云开发。关卡、目标、奖励和装饰配置随包提供；存档写入当前设备。关卡、收藏、个人最佳成绩都可离线使用。
- **功能边界**：不安排全球/好友排行、云存档、赠礼、远程活动配置、联网领奖或上传分析事件；本阶段不做跨设备同步。
- **玩法调整**：去掉的是清一色等额外配对限制；新机关仍围绕相同麻将的配对、位置和可见目标展开。

牌面对比见 [tile-study.html](tile-study.html) 与 [实物牌前后对比](screenshots/tile-comparison.png)，来源是修改前后的真实绘制代码。

### 优先解决的三件事

1. **规则可信**：同牌能消，障碍可以看出来，目标不用背口诀。
2. **操作有反馈**：按下、拖移、落位、破冰、连消有不同声音和视觉层次。
3. **通关有去处**：完成一桌 → 领取花笺 → 点亮庭院 → 前往新地点。

## 2. 核心循环与基本规则

一局以 1–3 分钟为初始设计目标，后期精巧关 3–5 分钟；这是需要试玩检验的目标，不是现有统计。

```text
选一处小景 → 看一眼目标 → 推移 / 点消 → 机关反馈 → 完成目标
                              ↓                      ↓
                       提示 / 撤销 / 重开       花笺 / 星级 / 小院装饰
                                                      ↓
                                                 下一处小景
```

- 点消：先点一张，再点相邻同牌。只有一个可配对邻居时，可以保留现有的一点快捷消除；设计稿用显式两次点击，便于观察选择反馈。
- 推移：按住一行或一列拖动，整段循环移动，松手后相邻同牌自动消除。
- 相邻：上下左右；不把斜角、隔空直线匹配混入主线规则。
- 空位随所在轨移动；木桩截断轨道，不能穿越。
- 普通推移即使没有消除，也允许用来摆位置；是否消牌与是否计步分开表达。
- 百搭保持可见的特殊标识；不用没有画出来的“某门只能点消”限制。
- 冰的正式改版建议：按底层牌面识别相同牌；若配对中任一张覆冰，此次只削去两侧存在的冰层、两张都不移除，待两侧均无冰再成对收走。这既保证“同款能作用”，也保持牌数成对。设计稿的破冰样例仍复用原版同冰层配对规则，该项需在正式规则重构中单独实现和回归。
- 过关先检查目标，再检查步数耗尽。最后一步达标就是赢。
- 主线优先限步，不把时间和步数两种预算同时压给新手。计时玩法放到独立入口。

### 保留、删除、改写

| 处理 | 内容 | 原因 |
| --- | --- | --- |
| 保留 | 推行推列、相邻点消、自动连消、叠层、冰、百搭、木桩 | 与麻将牌形一致；能直接看见并解释 |
| 保留并强化 | 单向轨、累计解锁、目标收集 | 用箭头、进度锁、图标目标清单呈现 |
| 删除 | 将将胡 / 只准 2、5、8 | 不再让长得相同的牌突然成为不能消的滑块 |
| 删除 | 幺九 / 只准 1、9 等 | 同上 |
| 删除 | 清一色、断门、双方言 | 花色不再决定点消和滑消是否有效 |
| 改写 | 八花齐、三元齐、清龙 | 可以保留牌面收集内容，名称改成“收集这些牌”，目标直接贴图；不要求玩家认识术语 |

## 3. 新玩法：增加决策，不再增加麻将知识

### A. 花圃开花 —— 第一优先级，已做可玩样例

**一句话：在金边花圃格上消掉麻将，这一格就开花。让所有花圃开花即可过关。**

花圃属于地板，不跟牌移动。玩家需要把对子送到指定位置；即使眼前有别的对子，也要考虑在哪里消更划算。普通牌仍按原规则消除。

- 视觉：土色金边格 → 小花芽 → 花朵展开；完成进度飞向目标栏。
- 计数：只有牌真正被收走才开花；仅碎冰不算。一次两张分别检查所在格。
- 已开花的格不重复计数，撤销同时还原花圃状态。
- 生成：先生成并重放清台路线，再从实际移除位置选花圃；不要随机把目标放到永远不会消牌的空洞上。
- 正式提示必须把未完成花圃加入搜索目标。清台却没开完花，不能判成功；提供可解释的重排或回退，不能留永久空目标。
- 样例：四朵花圃，取自同一条认证路线上的消除位置。

### B. 心愿收集 —— 第一优先级，已做双目标样例

**一句话：把目标清单上画出的两种牌，各收一对。别的同牌照常能消。**

现有 `goal` 收集能力值得保留；新增价值是多个清楚可见的小目标、组合次序与完成反馈，而不是把旧收集改个名字宣称全新规则。

- 每项显示真实牌面、已收数量和勾选标记，例如“一对二筒、一对发财”。
- 所有移除都记账，非目标牌也能消并帮助腾位置。
- 复杂度从单目标 → 两目标 → 两段目标清单。首次只出现两张目标图标。
- 两段目标清单采用**全局收集账本**：早收的第二阶段牌保留计数，避免“牌已经消完，下一张目标清单才要它”的死局。
- 目标牌必须真实存在且数量充足，不能依赖途中随机刷牌。

### C. 灵感充能 —— 第一优先级，已做可玩样例

**一句话：每收走一对麻将，点亮一格；四格满了，领一次免费慧眼。**

奖励从玩家正常消除中产生，给拖移和连消带来明确正反馈。慧眼只指路，不会偷偷替玩家删牌。

- 普通移除计能量，仅碎冰不计；一次连消多对可以快速充满。
- 能量可暂存，满格后由玩家主动用；不强制马上领取。
- 提示找到有效动作才扣能量；找不到就保留充能。
- 能量不以秒衰减，避免把轻松益智变成拼手速。连续有收获的手数只负责赞赏文案与小动画。
- 撤销回滚能量和收集账本，不能反复撤销刷能量。
- 正式版本免费基础提示与能量慧眼统一到同一资源模型，避免底栏出现两个完全相同、却无法理解区别的按钮。
- 设计稿为验证机关，基础提示不限次，四格慧眼可实际使用；这不是最终道具经济参数。

### D. 钥匙开门 —— 第二批

**一句话：收走带钥匙的牌，打开同色门，腾出新的推移路线。**

钥匙附着于牌块并随牌移动；门附着于地板。二者用颜色、形状和连线同时对应，不能只靠红绿区分。

- 第一关只一把钥匙、一扇门，钥匙就在眼前，开门能立即看见收益。
- 门阻断轨道，不规定哪种麻将能消；被门挡住时另一方向仍能移动。
- 钥匙在实际移除时掉落，碎冰不掉落；撤销同时关门还原钥匙。
- 不把钥匙放在自身门后。关卡求解状态必须包含门和钥匙，不只验证初始棋盘。
- 实现使用稳定 tile ID 与 sidecar 附件数据，不能用“当前坐标上的某张牌”代替移动中的钥匙身份。

### E. 转盘移位 —— 第二批

**一句话：每完成一次消除，带箭头的小转盘把上面的牌转一格。**

用明确的自动位移产生计划空间，替代断门这类操作规则例外。

- 首次只做 2×2 顺时针环；箭头常驻，松手前可预览下一位置。
- 一次玩家事务结束后触发一次，不能连消一层就触发一次形成无限循环。
- 顺序固定为：玩家移动 → 连消稳定 → 目标记账 → 转盘 → 一轮合法连消 → 判胜负。
- 循环传送不能把同一张牌复制两次，附件随牌移动；各阶段都必须有事件可重放。
- 初期不与单向轨、门和厚冰一起出现。稳定后才安排“转盘 + 花圃”的位置规划关。

### F. 锦盒藏珍 —— 第二批

**一句话：消掉盖在锦盒上的牌，收走底下的纪念物。**

以“露出新东西”的正反馈替换重复的厚冰磨耗。宝物固定在地板下，揭开以后立即计目标，奖励不挤占麻将牌池。

- 一个锦盒一层盖牌；先不做三层盒中盒。
- 收集宝物不改同牌规则，也不把随机奖励用于决定关卡可解性。
- 纪念物成为本章花笺的一部分，通关页能看到归属。

### 机制组合约束

| 组合 | 价值 | 上线顺序 |
| --- | --- | --- |
| 叠层 + 双份目标 | 选择先露哪张目标牌 | 第一批 |
| 冰 + 灵感 | 选择先破冰还是先攒提示 | 第一批 |
| 花圃 + 推移 | 消除位置变成决策 | 第一批 |
| 花圃 + 转盘 | 预判目标格与未来位置 | 第二批 |
| 钥匙 + 锦盒 | 先解锁路线，再揭开奖励 | 第二批 |
| 限时 + 门 + 转盘 + 厚冰 | 学习成本叠加、反馈难追踪 | 不做主线组合 |

## 4. UI：具体怎么变好看

### 视觉系统

| 层级 | 设计 | 作用 |
| --- | --- | --- |
| 大背景 | 浅米白底、柔和日光、低对比绿叶与小花 | 有空间、有氛围，不影响看牌 |
| 主场景 | 微俯视青绿牌桌，乳白厚麻将、花盆和小花笺 | 不看文字也能认出是麻将消除 |
| 牌桌框 | 浅青桌沿、细白边、下沿明确投影 | 形成“放在桌上”的深度 |
| 桌垫 | 深青绒面、细微纹理、中心柔光 | 浅色麻将清楚分离 |
| 牌块 | 乳白正面、细倒角、微光、青绿背板、接触阴影 | 强化按压与移动手感；重画可辨认的竹节 |
| 按钮 | 杏桃主按钮、青绿次按钮；厚底与按下位移 | 行动重点清楚，避免所有按钮都是绿色长条 |
| 机关 | 冰裂、铜钥匙、土色花圃、纸质目标清单 | 每种机制有独立的材质身份 |
| 文字 | 游戏名清晰圆润黑体，章节保留少量楷体，数字独立层级 | 轻松语气与阅读效率兼顾 |

色值：深绿 `#164F44`、桌垫 `#42795D`、浅米白 `#FBFCF4`、杏桃 `#D98970`、浅金 `#C6AF75`。颜色是辅助，牌种还靠图案，机关还靠形状。

正式 Cocos 若需要固定字形，应只打包标题所需字形或位图标题；不可假设各手机都内置桌面楷体。正文用系统字体并实测缩放。原型字体降级不影响操作。

### 各屏内容

**首页**：头像和真实星数 → 游戏完整名称 → 日光花园主视觉 → 当前目的地与开局主按钮 → 两个次入口 → 底部四栏。不会同时堆商店、广告、签到、礼包、排行榜六个红点。

**牌局**：顶部左暂停、右设置；中央章节名。第二行目标图标和剩余步数，第三行充能。中间最大面积留给牌桌，底部才是短句提示和道具。长篇章说明不挡首个动作。

**地图**：用一条游园路径连接地点，每章一个场景轮廓和代表机关；进入章节以后再展示本章小关。未解锁地点能看主题和解锁条件，星级不强制卡主线。

**机关工坊**：可重玩的短小教学关。玩家遇到不懂的机关能点开亲手试一次；从对局打开时暂停并保留原盘。

**收藏**：花笺、桌布、少量庭院摆件。进度直接由通关驱动，不额外引入收菜计时、合成、体力和货币兑换链。

**结算**：先给视觉奖励，再给关卡信息。显示真实用步、星级、解锁的花笺；主按钮下一关，次入口查看收藏。花笺同一关首次获得，重复通关只更新最好成绩，不能刷无限奖励。

**失败**：说明“差几张 / 哪个目标还没完成”，给可行出路。免费重开永远在；激励续步是可选项，接口接入前不显示“看广告”假入口。

### 动效与操作规范

- 按压：约 80ms 压低 2px，松开回弹；选中的麻将升起 4–6px。
- 拖移：直接跟手；轨道边界与循环方向可见，临界位置有吸附提示。正式版需要循环边缘幽灵牌，不能只靠手指猜回绕位置。
- 消除：短促收拢 → 亮点 → 目标处飞入；160–240ms 结束，不串成长等待。
- 破冰：约 120ms 冰裂、清脆声；牌仍留下。不要用“消失”动画误导。
- 开花：约 250ms 小幅展开；目标栏加一。无需全屏白闪。
- 连消：先标示“连消 2 层”，再强化声音与轻微光圈；不遮住下一次操作。
- “减少动态效果”关闭飘落、飞行和大幅位移，保留瞬时状态变化。
- 动画期间防止同一动作重复提交；暂停、后台切换、中途重载后不能重复结算。

### 手机尺寸

- 设计基准 390×844；覆盖 320×667、430×932 和安全区。
- 常用按钮点击热区至少 44×44 CSS px；牌面虽小于按钮热区，也应把整格用作触摸目标。
- 主线优先 4–6 列，不再用 10 列超密盘吸收难度；增加行数不能把目标和道具挤出一屏。
- 牌局短屏优先收紧装饰与间距，避免牌桌必须上下滚动才能操作。原型支持页面滚动作为兜底，正式验收要求主操作一屏可达。
- 纹理只作装饰，关闭或加载失败也不影响牌面、机关和目标可读。

## 5. 224 关重编，而不是只删一个字段

`dialect` 已参与牌池、可消数、生成证书、提示、洗牌、教学和存档。直接删关卡 JSON 的字段，不能保证原来被冻结的关卡仍有同样的路线、分数和难度。

### 建议的 14 章主题

保留 14×16 的关号规模作为内容组织框架，但每章重做机关配置。名称是本次的设计提案。

| 章 / 关号 | 主题 | 代表变化 | 新手或组合安排 |
| --- | --- | --- | --- |
| 1 / 1–16 | 清风入席 | 点消、推移、少量叠层 | 第 1 关马上完成点消；第 2 关教推移；第 7 关首次叠层 |
| 2 / 17–32 | 双层小院 | 叠层与路障 | 控制到两层，观察下一层目标；不同时上锁行和锁列 |
| 3 / 33–48 | 冰晶花园 | 冰与鞭炮 | 先单独破冰，再教一次可见范围的爆破 |
| 4 / 49–64 | 花圃初开 | 位置目标 | 先两个花圃，再四个；位置选择代替更多牌种 |
| 5 / 65–80 | 心愿收集 | 可视化目标清单 | 一目标到双目标，不使用限时施压 |
| 6 / 81–96 | 钥匙廊桥 | 钥匙与门 | 替代将将胡，先单门再两条可选路线 |
| 7 / 97–112 | 转盘花园 | 固定位移 | 替代断门，先单 2×2 环再与花圃组合 |
| 8 / 113–128 | 灵感连消 | 灵感与连消 | 替代幺九，体现先攒能量再用提示的选择 |
| 9 / 129–144 | 锦盒藏珍 | 揭开锦盒 | 替代清一色，目标是揭开而非筛掉花色 |
| 10 / 145–160 | 百花小筑 | 花牌与百搭 | 使用图标目标清单，保留收集意象 |
| 11 / 161–176 | 风铃工坊 | 累计解锁 | 显示每消一对锁的进度；复用现有 `unlock` |
| 12 / 177–192 | 双段心愿 | 两段目标 | 早期收集统一入账，避免错过目标清单 |
| 13 / 193–208 | 奇巧回廊 | 精选双机制 | 替代双方言，主打花圃+转盘、钥匙+锦盒 |
| 14 / 209–224 | 观星雅集 | 精选综合 | 每关最多三种特殊机制，不是全机制随机混装 |

### 难度曲线

每组四关：**认识 → 练习 → 组合 → 爽关**。爽关可安排一次明显连消，让玩家喘口气，不能 224 关只往上叠障碍。

建议初期范围：

| 阶段 | 牌面种类 | 总牌数（包含叠层） | 机关 | 目标时长 |
| --- | --- | --- | --- | --- |
| 入门 | 4–6 | 8–24 | 0–1 类 | 30–90 秒 |
| 中段 | 6–9 | 24–36 | 1–2 类 | 1–3 分钟 |
| 后段 | 8–12 | 32–48 | 2 类为主，少量 3 类 | 3–5 分钟 |

现有“每面最多四张”约束仍成立时，必须满足 `总牌数 ≤ 4 × 牌种数`，并保证可配对的奇偶计数。不能只把 `faces` 从 34 改成 8，而保留超过 100 张的旧盘。

少量关卡可放宽每面四张的麻将实物约束，但这属于另一项明确规则变更，需要同步 `stateLegal`、存档、生成器和测试；第一批不建议扩大范围。

限步根据**最终机关状态下的已认证路线**派生，不按经验随手填。目标关以到达目标的路线计基准，不用清台路线给星级。前三关不失败，不插广告。

### 挑战模式

现有独立挑战的“隔着空格也能同线配对”与主线相邻规则不同。建议先收起首页同权重入口，放到游园的进阶区域，完成主线教学后再出现。

第一阶段把尺寸改成渐进的 5×5 → 6×5 → 7×6，密度与牌种分别调；最高列数受实际触摸尺寸约束。不要从第 2 盘直接跃升到 14×10。

挑战记录仅保存本机最佳成绩与最近成绩。当前不做“全服同盘”“好友排行”等联网承诺；不接服务端，不增加防作弊、账号或运维工作。

## 6. 教学：第一次操作就是理解

每个机关只在首次出现时教一次，随时能在工坊重玩。

1. 第 1 关摆明显同牌，轻提示“点这两张”，成功立即反馈；不先读四行说明。
2. 第 2 关同牌错一格，用短箭头和幽灵牌演示拖一格；接受所有合法等价解，不强制只认内部某条证书。
3. 首次冰：第一下碎裂后停半秒，字幕“冰碎了，再收牌”；玩家自己点第二次。
4. 首次花圃：两朵花就在第一次消除的位置，开花飞进目标栏，完成一个十秒教学小关。
5. 首次转盘：允许预览并回退，清楚展示“消完一次才转”，不要求记后台事务顺序。

保留引导状态机与证书验证基础；新引导键与旧机制卡分开版本化。旧麻将限制教学不再出现在首次触发或帮助页。

## 7. 工程落地与存档

### 模块边界

| 模块 | 改造职责 |
| --- | --- |
| `Rules.ts` | 基础配对保持可信；新机关通过明确事务和事件接入，所有状态可重放 |
| 新 `Mechanics.ts` | 地板花圃、钥匙门、转盘、锦盒；产出领域事件，不依赖 Cocos |
| `Generator.ts` 与编排工具 | 生成包含机关状态的证书；绑定关卡版本、种子与指纹 |
| `Session.ts` | 目标、能量、道具、撤销快照、结算、防重复奖励、存档版本 |
| 共享内容表 | 章名、机关描述、目标文案、图标键；H5/Cocos 同源 |
| `art.ts` / `assets.ts` | 共用牌面与新增机关图集；所有命名有缺帧验证 |
| `Board.ts` | 牌面、地板、附件分层；拖移预览、循环幽灵牌、事件动画 |
| `GameRoot.ts` | 页面布局和场景流，不复制玩法判定 |

建议动作结果从仅 `erased` 扩充为有序事件，例如 `PairRemoved`、`IceCracked`、`FlowerBloomed`、`KeyCollected`、`GateOpened`、`EnergyAdded`。视图按事件播放；目标计算只在核心层发生，不能按动画结束次数给分。

### 本地架构，无服务器依赖

当前正式版通过 `GameRoot.ts` 的 `Platform` 适配层使用 Cocos `sys.localStorage` 保存主线和挑战；在微信环境由引擎映射到平台本地存储。沿用这一层，避免让核心规则直接依赖 `wx` 或任何网络 API。

| 数据/能力 | 本阶段实现 |
| --- | --- |
| 关卡、机关、主题配置 | 构建时打包，本地读取；内容更新随游戏版本发布 |
| 当前局、已过关、星级、个人最佳 | 本地版本化存档；动作提交后保存，恢复时验证关卡版本 |
| 花笺、桌布、解锁状态 | 本地固定奖励表；首次通关记账，重复通关只更新最佳记录 |
| 提示与可解性 | 本地规则搜索与关卡证书，不发起接口请求 |
| 设置 | 本地音效和减少动态效果偏好 |
| 试玩统计 | 人工观察；必要时开发模式本地日志，不上传 |

本设计稿使用独立 `localStorage` 键 `mahjong:design-study:v1` 保存星级、花笺、桌布和偏好，不写正式小游戏存档。已验证完整断网下的指针操作通关，以及本地 HTML 冷启动、获奖、刷新后恢复收藏与桌布。存储归属当前设备；清理应用数据或换设备不会自动恢复，设置页已说明不支持跨设备同步。

### 老关卡和存档

- **保留所有现有本地进度，先在设备上备份再迁移。** 不能继续沿用旧文档“尚无用户，可直接丢档”的假设。
- 新增 `rulesVersion` / `levelContentVersion`，不能只靠存档容器版本判断正在玩的盘面。
- 已通关、星数和累计装饰可保留；重做关卡的历史 `par`、最佳步数和分数应记录为旧版本成绩，不混入新版个人最佳记录。
- 正在玩的旧限制关，不把旧格子塞给新引擎。保存旧盘备份，重开对应新版关，并用简短提示说明关卡已更新。
- 关号映射先保持一对一；若需要改章节关数，必须生成显式映射表。
- 删除旧限制入口与可见文案后，再逐步清理兼容代码。不要在同一次提交里顺手删除无法验证的历史数据。

### 性能与资源

- 保留当前烘焙图集的优势：牌、机关、按钮一次生成复用；不把每张牌改成实时复杂 Graphics。
- 场景插画单独一张背景或拆成少量层；原型用 SVG/CSS 证明视觉方向，正式版转为引擎资产，不能直接嵌 DOM。
- 机关状态变化重绘必要节点，拖动只改位置；不能每帧重建牌桌。
- 低端机优先静态材质、短动画；减少多层半透明光效、全屏模糊和高分辨率临时画布。
- 微信包体、纹理上限、Draw Call 与低端机帧率是实际验收项，不从桌面浏览器结果推断真机表现。
- 正式构建继续走 `npm run build:wechat` 与编辑器扩展，遵守现有构建配置和资源校验；不要改走仓库明确禁用的 CLI 构建入口。

## 8. 开发顺序和验收

### 第一批：先把“好懂 + 好看”做实

1. 从新章表和共享文案入手，制作前 48 关重编样本；取消样本内所有花色/点数限制。
2. 新首页、牌桌、目标栏、暂停和结算接入 Cocos，保留现有输入和图集机制。
3. 接入花圃、双份目标、能量，加入真实教学与花笺奖励。
4. 逐关证明可解，走一次从首次安装到第一个新机关的完整路径。

验收：不同点数和花色的同牌一律可消；破冰不会误计收集；最后一步获胜；撤销全状态一致；提示不把人带进不可恢复目标；无教学/暂停重复计时；所有入口可返回；微信短屏上目标、牌桌、道具一屏可达。

### 第二批：再建立空间规划深度

1. 实现钥匙门、转盘与锦盒事务和求解。
2. 重编剩余章节，逐批替换 80 个旧限制关及其他受曲线影响的关。
3. 地图主题和庭院装饰拓展，替换 H5 中重复的玩法说明。
4. 挑战缩盘与渐进曲线，完善本地个人最佳成绩。

验收：钥匙随牌移动、门不会自锁；转盘一次事务只触发一次、无复制牌或循环；阶段目标清单不能因提前收牌而无解；224 关新版本指纹、预算与证书全部过检。

### 第三批：用试玩结果调节

采用本地试玩和人工观察记录。必要的 `first_match`、`invalid_action`、`hint_used`、`level_end`、`retry` 仅留在开发模式的本地日志，不接分析 SDK、不上传事件。邀请的试玩者数量和观察结论如实记录，不伪造线上转化数据。

重点看：首局完成率、首次机关理解所需动作数、无效操作比例、同一关连续失败次数、提示后完成率、玩家是否返回收藏。先比较有无新机关的同难度关，不把“广告点击上涨”当成玩法改善证据。

目标是减少“我为什么消不了”和“我现在该做什么”，而不是只增加停留时长。
